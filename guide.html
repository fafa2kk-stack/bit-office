02 · A DAY

하루가 돌아가는 순서

일봉 전략이라 하루에 한 번만 판정합니다. 나머지 시간엔 폰의 지시만 확인하며 기다립니다.

  1. 09:00
    일봉 마감바이낸스 기준 자정(UTC) = 한국 09:00. 어제 하루 캔들이 확정됩니다.
  2. 09:03
    봇 판정최근 400일 시세 → 종가와 200일선 비교, 하락장이면 20일 저점 이탈 확인 → 롱 / 현금 / 숏 결정. 가디언이 한도 검사.
  3. 09:03
    주문 (거래 시작이 켜져 있을 때만)목표 포지션과 지금 포지션이 2% 이상 다르면 시장가로 맞춥니다. 같으면 아무것도 안 합니다. 보통은 "유지"가 대부분이라 한 달에 몇 번 거래합니다.
  4. 09:04
    보고자산·포지션·판정·다음 판정 시각을 status.json으로 올립니다. 폰 앱 실제 봇 탭에 바로 뜹니다.
  5. 10분마다
    지시 확인control.json을 읽어 거래 시작/중지, 전량 청산, 거래 방식 변경을 반영합니다. 전량 청산은 기다리지 않고 바로 실행합니다.
  6. 다음날
    반복PC가 켜져 있고 start_bot 창이 살아 있는 한 매일 반복. 내가 아무것도 안 눌러도 규칙대로 갑니다.
03 · FIRST TIME

처음 한 번 설정 (10분)

열쇠 두 개를 꽂는 작업입니다. 바이낸스 키는 봇이 거래소에 들어가는 열쇠, GitHub 토큰은 봇과 폰이 같은 우체통을 쓰는 열쇠.

  1. 바이낸스 모의(Demo) API 키 → .env

    바이낸스 계정으로 demo.binance.com 로그인(가상 USDT 자동 지급, 신분증 인증 불필요) → 우상단 계정 아이콘 → API Management → Create API → System generated → OTP → Key / Secret 복사 (Secret은 그 화면에서만 보임). 권한은 Enable Futures만 켜고 출금은 절대 켜지 않습니다. 문서\crypto_backtest\.env를 메모장으로 열어 BINANCE_API_KEY=, BINANCE_API_SECRET= 뒤에 붙여넣고 저장. BOT_TESTNET=1, BOT_DEMO=1은 그대로 (가짜 돈). 자세한 순서는 PC의 TOMORROW.md 1번.

  2. GitHub 토큰 → .env 와 폰 앱, 둘 다

    github.com → Settings → Developer settings → Fine-grained tokens → Generate. Repository access는 bit-office만, Permissions는 Contents: Read and write만, 만료 1년. 받은 github_pat_...을 .env의 GITHUB_TOKEN= 뒤에 붙이고, 폰 앱 실제 봇 탭 → "연결" 칸에도 붙여넣고 [저장하고 연결 확인].

  3. PC에서 봇 켜기

    setup.bat 한 번 (처음만, 라이브러리 설치) → run_once.bat 더블클릭해서 창에 standby 또는 hold가 뜨고 빨간 에러가 없으면 OK → start_bot.bat 더블클릭하고 창을 켜둡니다. 이 창이 봇입니다. 폰 앱에 "봇 연결됨"이 켜집니다.

  4. 폰에서 ▶ 거래 시작

    실제 봇 탭 → ▶ 거래 시작 → 확인. 봇이 10분 안에 읽고, 다음 09:03 판정부터 주문을 냅니다. 모의로 몇 주 지켜본 뒤 실계좌 키로 바꾸고 BOT_TESTNET=0.

토큰을 넣기 전엔 봇이 .env대로 바로 거래하고, 넣은 뒤부터는 폰에서 거래 시작을 눌러야 주문이 나갑니다. 그 전까진 매일 판정만 하고 standby로 기록합니다.
04 · THE APP

앱 화면 안내

탭 네 개: 사무실 · 실제 봇 · 차트·규칙 · 기록. 폰 브라우저에서 열고 "홈 화면에 추가"하면 앱처럼 씁니다.

사무실 탭 — 회의를 구경하는 곳

  1. 시황 데스크 (5명) 차트·모멘텀·변동성·수급·심리가 각자 숫자를 보고합니다. 말풍선이 순서대로 뜹니다.
  2. 리서치 (3명) 매수파와 매도파가 근거를 대고, 팀장이 "결론은 규칙이 낸다"로 정리합니다.
  3. 트레이딩 본부 · 리스크 위원회 숏데스크가 저점 이탈을 확인, 리스크가 한도를 검사, 사이저가 수량을 계산, 트레이더가 주문 문장을 읽습니다.
  4. 대표 결재 마지막 말풍선. 아래 오늘의 결재 카드에 같은 결론이 롱(초록)·현금(파랑)·숏(빨강)으로 뜹니다.
  5. 재생 버튼 ▶ 하루 진행은 과거 하루씩, ⏩ 자동 재생은 쭉, ⏭ 오늘(최신)로는 실제 오늘 회의. 이건 모의 계좌(가짜 1만 달러)라 실제 돈과 무관합니다.
  1. 모의 계좌 같은 규칙으로 1만 달러를 굴렸을 때의 자산·누적·최대 낙폭·존버 비교. 실제 돈이 아니라 연습용. 실제 봇 숫자는 실제 봇 탭에 따로 있습니다.
  2. 거래 방식 차트·규칙 탭에서 현물/선물/하이브리드를 바꾸면 모의 계좌가 처음부터 다시 돕니다.

실제 봇 탭 — 리모컨

  1. 상태 칩 봇 연결됨(초록) / 보고 오래됨(주황) · 거래 켜짐/꺼짐 · 거래 방식 · 앱↔GitHub 연결.
  2. 숫자 타일 실제 계좌의 자산·포지션·마지막 판정·가디언·다음 판정 시각·테스트넷/실계좌. 봇이 마지막으로 보고한 값입니다.
  3. 큰 버튼 3개 ▶ 거래 시작 / ⏸ 거래 중지 / ⛔ 전량 청산 후 중지. 누르면 확인 창이 한 번 더 뜹니다.
  4. 설정 거래 방식(현물·선물·하이브리드)과 숏 비율. [설정 저장]을 눌러야 반영됩니다.
  1. 연결 GitHub 토큰을 한 번 넣습니다. 이 폰에만 저장되고 GitHub에만 보내집니다. 바이낸스 키는 여기 넣지 않습니다 (PC에만).
  2. 체크리스트 봇 첫 보고, 토큰, 봇 연결, 거래 시작이 되면 자동으로 체크됩니다.

차트·규칙 탭, 기록 탭

  1. 차트 흰 선 종가, 노란 선 200일 이동평균, 분홍 선 20일 저점. 초록 띠는 롱 보유, 빨간 띠는 숏 보유 구간.
  2. 규칙 카드 세 규칙과 "지금" 값. 종가가 노란 선 위면 롱, 아래면 현금, 아래에서 분홍 선까지 깨면 숏.
  3. 기록 탭 날짜별 종가·MA200·신호·결재·자산 표. 모의 리플레이의 일지입니다. 실제 봇의 일지는 PC의 state\journal.jsonl.

06 · RULES

규칙과 성적

2017년부터의 바이낸스 일봉으로 수백 개 조합을 걸러 살아남은 것만 씁니다. 수수료·슬리피지·펀딩은 보수적으로 넣었고, 1분~1시간봉은 수수료 때문에 전부 탈락했습니다.

롱

종가 > 200일 이동평균이면 롱 100%, 아니면 현금. 상승 추세에 타고 하락 추세엔 비켜 섭니다.

숏

200일선 아래(하락 레짐)에서 20일 저점을 종가로 깨면 숏 50%, 12일 보유 후 청산. 하락장에서만 짧게.

리스크

당일 −8% 또는 고점 대비 −45%면 전량 청산 후 정지. 하루 주문 3건 초과, 오래된 데이터, 가격 급차이, 레버리지≠1이면 주문 차단.

2022~2026 (학습에 안 쓴 구간), 1만 달러 시작최종최대 낙폭
그냥 존버1.74배−67%
선물 (롱+숏, 펀딩비 냄)3.29배−37%
현물 (롱만, 펀딩비 없음)3.43배−32%
하이브리드 (롱은 현물, 숏은 선물)4.27배−35%

연 복리로 25~30%대, 거래는 한 달에 몇 번. 과거 성적이 미래를 보장하진 않지만, 과최적화를 걸러낸 숫자라 "유튜브 1,000%"류와는 결이 다릅니다. 떨어지는 해도 있습니다. 최대 낙폭 −35%는 "계좌가 한때 35% 줄어든 적이 있다"는 뜻이니 그걸 견딜 금액으로만.

07 · MONEY & SAFETY

돈은 어디 있고, 뭐가 막아주나

잔액
바이낸스 계정에 그대로. 봇은 주문만 냅니다. 기본 방식(하이브리드)은 롱을 현물 지갑에서, 숏을 선물 지갑에서 하며, 진입 전에 두 지갑 사이의 USDT를 봇이 알아서 옮깁니다. 이체가 안 되는 환경(모의거래 등)에선 각 지갑에 든 금액이 그 다리의 한도가 됩니다. 실계좌라면 돈은 현물 지갑에 넣어두면 됩니다.
API 키 권한
거래만. 출금 권한은 절대 켜지 않고, 가능하면 IP 제한. 키는 PC .env에만 있고 GitHub·폰에는 없습니다.
레버리지
1배 고정 (코드에 박혀 있고, 거래소 설정이 1배가 아니면 가디언이 주문을 막음). 강제청산 위험은 사실상 없습니다.
가디언
매 판정마다 한도 검사. KILL 파일이나 앱의 kill이 있으면 아무것도 안 함. 한도를 넘으면 전량 청산 후 HALT 파일을 남기고, 사람이 지우기 전엔 다시 안 움직입니다.
기록
모든 판정과 주문은 PC state\journal.jsonl에 한 줄씩. 보여주면 "그날 왜 그랬는지" 설명할 수 있습니다.
지금 당장 멈추기
폰: ⛔ 전량 청산 후 중지. PC: start_bot 창 닫기 (주문은 더 안 나가고 포지션은 남음). 바이낸스 앱에서 직접 청산해도 됩니다. 봇은 다음 판정 때 거래소 포지션을 다시 읽어 맞춥니다.
08 · TROUBLE

막히면

증상원인과 해결
start_bot 창이 바로 꺼짐.env에 키가 없거나 오타. run_once.bat로 돌려 빨간 줄을 읽고, 그 줄을 복사해서 클로드에게.
앱에 "봇 보고 오래됨"PC가 꺼졌거나 start_bot 창이 닫혔거나 인터넷이 끊김. 다시 더블클릭.
버튼 눌렀는데 "저장 실패"GitHub 토큰 권한 확인: 레포 bit-office, Contents: Read and write. 만료됐을 수도.
거래 시작 눌렀는데 주문이 없음정상일 수 있음. 판정은 09:03에만, 그리고 목표가 지금 포지션과 같으면 "유지"로 주문 없음. 실제 봇 탭의 마지막 판정 칸을 보세요.
PC를 껐다 켰다start_bot.bat 다시 더블클릭. 포지션은 거래소에 그대로 있고 봇이 읽어옵니다.
클로드 아티팩트 화면에선 버튼이 안 됨그 화면은 네트워크가 막힌 미리보기. 폰·PC 브라우저에서 fafa2kk-stack.github.io/bit-office 를 여세요.

현물 / 선물
현물은 코인을 진짜로 사고팜(롱만, 펀딩비 없음, 수수료 0.1%). 선물은 계약이라 숏도 됨(수수료 0.05%, 8시간마다 펀딩비).
하이브리드
롱은 현물 지갑, 숏은 선물 지갑. 롱에 펀딩비를 안 내서 백테스트 성적이 가장 좋음.
펀딩비
선물에서 롱과 숏이 8시간마다 주고받는 소액. 보통 롱이 냄 (연 10% 안팎).
MA200 / 레짐
200일 평균 가격. 그 위면 상승 레짐, 아래면 하락 레짐으로 봅니다.
가디언
봇 안의 안전장치 모듈. 한도를 넘으면 주문을 막거나 전량 청산합니다.
GitHub 토큰
레포의 파일 하나를 고칠 수 있는 열쇠. 소모되지 않고 만료일만 있음. 돈과 무관.
status / control
봇의 보고서와 폰의 지시서. 레포에 있는 작은 파일 두 개.
10 · API KEYS

바이낸스 API 연동, 처음부터 끝까지

API 키는 "이 프로그램이 내 계정으로 주문해도 된다"는 열쇠입니다. 모의거래(Demo) 키로 먼저 연습하고, 실계좌 키는 같은 방법으로 나중에 만듭니다.

  1. 바이낸스 계정

    binance.com → 가입(이메일) → 메일 인증 → 보안에서 구글 OTP 켜기. 모의거래엔 신분증 인증(KYC)이 필요 없고, 실거래·입금 때 필요합니다. 가입 이름·생년월일은 업비트와 똑같이 (나중에 송금 조건).

  2. 모의거래 켜기

    demo.binance.com 접속 → 로그인 → 처음이면 "Demo Trading 활성화" → 현물·선물 지갑에 가상 USDT가 들어옵니다. (앱: 더보기 → Demo Trading)

  3. 키 만들기

    demo.binance.com 우상단 계정(프로필) 아이콘 → API Management → Create API → "System generated" → 이름 bitoffice → OTP → 화면에 API Key와 Secret Key. Secret은 그 화면에서만 보입니다. 닫으면 다시 못 보니 바로 복사. (잃어버리면 키 삭제 후 재발급)

  4. 권한 (Edit restrictions)

    ✅ Enable Spot & Margin Trading (현물) ✅ Enable Futures (선물) — 둘 다 켜야 하이브리드가 됩니다. ❌ Enable Withdrawals는 절대 켜지 않습니다 (키가 새도 돈을 못 뺌). IP 제한: 집 IP가 고정이면 PC 공인 IP 입력, 아니면 Unrestricted.

  5. .env에 붙여넣기

    문서\crypto_backtest\.env를 메모장으로 열고 BINANCE_API_KEY=, BINANCE_API_SECRET= 뒤에 바로 붙여넣기(공백·따옴표 없이) → 저장. BOT_TESTNET=1, BOT_DEMO=1, BOT_VENUE=hybrid는 그대로. 파일 이름이 .env.txt로 바뀌지 않았는지 확인.

  6. 확인

    run_once.bat 더블클릭 → connected: DEMO hybrid …와 standby(또는 hold)가 뜨면 성공. 에러 -2015 → 권한·IP 제한, -1022 → Secret 오타, Invalid API-key → 실서버 키와 모의 키를 바꿔 썼거나 BOT_DEMO 값 확인.

  7. 업비트로 돌리기 (선택, 송금·KYC 없이 롱만)

    upbit.com → 마이페이지 → Open API 관리 → ✅ 자산조회 ✅ 주문 (❌ 출금) → 허용 IP에 PC 공인 IP(네이버 "내 IP") → 발급 → Access key / Secret key를 .env의 UPBIT_ACCESS_KEY, UPBIT_SECRET_KEY에, BOT_VENUE=upbit. BOT_TESTNET=1이면 주문을 보내지 않는 드라이런, 며칠 보고 0. 업비트 계좌엔 원화만 넣어두면 되고 숏은 없습니다 (백테스트 3.49배).

  8. 실계좌로 전환 (나중에)

    binance.com 실서버 → 프로필 → API Management → Create API → 같은 방식. Enable Futures는 선물 계정을 먼저 개설해야 체크됩니다. KYC 필요, 출금 권한 금지, IP 제한 권장. .env의 키 교체 + BOT_TESTNET=0. 지갑엔 잃어도 되는 USDT만.

11 · UPBIT → BINANCE

업비트에서 바이낸스로 코인 보내기

이 장은 바이낸스로 돌릴 때만 필요합니다 (업비트 방식이면 건너뜀). 바이낸스는 원화를 못 받습니다. 업비트에서 코인을 사서 바이낸스 지갑으로 보내고, 거기서 USDT로 바꿉니다. 업비트 기준 바이낸스는 "계정주 확인 연동 거래소"라 100만 원 이상도 본인 계정으로는 보낼 수 있습니다 (2026-10 기준).

  1. 조건 맞추기

    업비트와 바이낸스의 이름(한글 또는 영문)과 생년월일이 같아야 합니다. 즉 바이낸스 KYC(신분증 + 얼굴 인증)를 먼저 끝내세요. 업비트는 원화를 넣은 뒤 일정 시간(첫 입금 72시간, 이후 입금·보안설정 변경 시 24시간) 코인 출금이 막히니, 보낼 날보다 미리 원화를 넣어두고 그 사이 이메일·OTP 같은 보안 설정을 바꾸지 마세요. 업비트 2채널 인증이 없으면 PC 웹에서만 출금됩니다.

  2. 무슨 코인으로 보낼까

    싸고 빠른 걸로. USDT (트론 TRC20): 업비트가 USDT 출금(트론망)을 지원하면 수수료 거의 0, 1~5분 도착, 바이낸스에서 그대로 USDT라 바꿀 필요 없음. 그게 안 보이면 XRP: 수수료 1 XRP 수준, 몇 초~몇 분 도착. 단 XRP는 주소 + 데스티네이션 태그 두 개를 모두 넣어야 하고, 태그를 빠뜨리면 코인이 사라집니다. 비트코인·이더리움은 수수료가 비싸서 송금용으론 비추.

  3. 바이낸스에서 받을 주소 복사

    바이낸스 앱: 자산 → 입금 → 코인 선택(USDT 또는 XRP) → 네트워크 선택(USDT면 Tron TRC20, XRP면 XRP) → 주소 복사. XRP면 아래 Tag/Memo도 복사. 네트워크가 업비트 출금 네트워크와 같아야 합니다 (다르면 분실).

  4. 업비트에서 출금

    업비트 앱: 입출금 → 코인 선택 → 출금하기 → 주의사항 확인 → 네트워크 확인, 수량 입력 → 지갑 종류에서 거래소 → 바이낸스 선택 → 받는 주소 붙여넣기(XRP면 태그도) → 동의 체크 → 개인정보 국외 이전 동의 → 계정 정보 확인 → 2채널 인증. 처음엔 소액으로 한 번 테스트하고 도착을 확인한 뒤 본 금액을 보내세요. 신청 후엔 취소가 안 됩니다.

  5. 바이낸스에서 USDT로

    도착하면 현물 지갑에 들어옵니다. XRP로 보냈으면 현물 거래 → XRP/USDT → 시장가 매도 → USDT. 하이브리드 봇은 현물 지갑의 USDT를 기준으로 움직이고, 숏이 필요할 때 선물 지갑으로 알아서 옮기니 그대로 두면 됩니다. (직접 옮기려면 지갑 → 전송 → 현물 ↔ USDⓈ-M 선물.)

  6. 알아둘 것

    100만 원 미만은 조건이 덜하지만, 쪼개서 여러 번 보내면 이상거래로 막힐 수 있습니다. 해외 거래소 자산이 연중 5억 원을 넘으면 다음 해 6월 해외금융계좌 신고 대상입니다. 바이낸스 쪽 입금은 KYC를 마친 본인 계정에서만 받습니다.

출금 화면에서 "바이낸스"가 목록에 없거나 조건이 달라져 있으면 업비트 고객센터의 "입출금 가능 가상자산사업자 리스트"를 확인하세요. 규칙이 자주 바뀌는 영역입니다.
12 · SECURITY

보안 — 뭐가 지켜지고, 내가 할 일은 뭔가

돈에 닿는 열쇠는 둘뿐입니다: 거래소 API 키(PC)와 GitHub 토큰(폰). 둘 다 "새어도 돈은 못 빼가게" 설계했고, 공용 와이파이에서도 통신은 전부 암호화(HTTPS)됩니다.

통신
앱·봇이 쓰는 모든 연결은 HTTPS. 공용 와이파이에서 누가 엿봐도 내용은 암호화돼 있고, 봇은 거래소 인증서를 검증합니다. 앱 페이지에는 CSP(콘텐츠 보안 정책)를 걸어 허용한 주소(GitHub·바이낸스·구글 폰트) 외엔 아무것도 불러오지 못하고, 끼워 넣은 스크립트는 실행되지 않습니다.
거래소 키 (PC)
권한은 거래만, 출금은 절대 켜지 않습니다 → 키가 새도 돈을 못 뺍니다. IP 제한을 걸면 다른 컴퓨터에선 아예 안 통합니다. 키는 PC의 .env에만 있고 GitHub·폰엔 없습니다.
.env 암호화
키를 넣은 뒤 protect_env.bat을 한 번 실행하면 비밀값이 Windows 보안 저장소(DPAPI)로 암호화되고 파일은 내 윈도우 계정만 읽을 수 있게 됩니다. 이 .env를 통째로 복사해 가도 다른 PC·다른 계정에선 열리지 않습니다. 키를 바꿀 땐 평문으로 적고 다시 실행.
GitHub 토큰 (폰)
권한은 레포 하나의 파일 편집뿐이라 새도 돈과 무관합니다. 앱에서 PIN을 넣고 저장하면 토큰이 PIN으로 암호화(PBKDF2 20만회 + AES-GCM)돼 저장되고, 앱을 열 때마다 PIN을 묻습니다. 폰을 남에게 넘기기 전엔 🔒 잠그기.
잔액 노출
status.json에 자산·포지션이 적힙니다. 기본 레포(bit-office)는 공개라 누구나 볼 수 있으니, 비공개 레포(예: bit-office-data)를 하나 만들어 PC .env의 GITHUB_REPO와 앱의 "데이터 레포" 칸에 넣으면 잔액은 토큰 있는 사람(나)만 봅니다.
기기
폰 잠금(지문·얼굴) 켜기. 거래소·GitHub 계정엔 2단계 인증(OTP). PC엔 윈도우 로그인 비밀번호. 봇 PC는 공용 와이파이보다 집 인터넷에서 돌리기(IP 제한도 그래야 가능).
절대 하지 말 것
거래소 키를 폰 앱·카톡·메모에 넣기, 출금 권한 켜기, 토큰이나 키를 캡처해 공유하기, "수익 인증"에 API 키가 보이는 화면 올리기.
